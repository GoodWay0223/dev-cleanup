# 定时清理与紧急清理

## 磁盘告急（可用空间低于 5 GB）

空间耗尽会让所有正在跑的会话写文件失败，先腾出空间，再做细致核验。按“代价低、把握大”的顺序：

0. 先查 git 残包 `.git/objects/pack/tmp_pack_*`（见 [缓存地图](cache-map.md) 的 Git 一节），磁盘快满时它们最容易突然冒出好几 GB；同时提醒用户告急期间不要让多个会话同时 fetch。
1. 包管理器缓存：`npm cache clean --force`、`pnpm store prune`、`brew cleanup --prune=all`，以及 [缓存地图](cache-map.md) 里其他工具自带的清理命令。
2. 没有对应进程时：Godot/clang 着色器缓存、智能体留下的 Chrome 测试配置目录。
3. 超过门槛的截图、录屏。
4. `worktree_report.py` 判定为 `removable` 的工作树。
5. 超过门槛的构建输出、发布暂存目录。
6. `mo clean < /dev/null`（较慢，放后面）。

每一步之后看一次 `df -h /System/Volumes/Data`。APFS 释放空间可能有延迟，删除量和实际增加的可用空间对不上是正常的，汇报时分开写。

做完仍然不够时，列出剩下的大项（有改动的工作树、SDK/NDK 旧版本、原始数据目录）让用户选，不要自行越界。

## 定时清理

用户要求“每天/每几天自动清理”时，用当前 harness 的定时任务功能，不改系统 crontab/launchd：

- Claude Code 桌面端：定时任务（scheduled tasks）。只在应用开着时运行，告诉用户。
- Codex：自动化（automations）。

定时任务的提示词要写全，因为它在新会话里运行，看不到当前对话：

- 读取本 Skill 的 `SKILL.md`。
- 本机的仓库与工作树目录、`--keep` 名单、`--asset` 规则、截图门槛（如 2 天）、构建输出门槛。
- 不碰的东西（如原始地图/数据目录、旧版本备份目录、SDK）。
- 只删本机、不碰 GitHub、不用 sudo、不清空废纸篓。
- 清理前后各量一次空间；清理后仍低于 10 GB 时在汇报开头醒目提醒。
- 用中文（或用户的语言）汇报：删了什么、依据、保留的大项及原因。

频率按空间增长速度定：多会话并行开发游戏时，一两天就能用掉 10 GB，应每天跑。

## 已知坑

- `mo clean` 没接 `< /dev/null` 时会等 sudo 密码而卡住；扫描受保护目录或“应用缓存”一步也可能卡住。超时设 600 秒左右即可，超时后已完成的部分有效；把 Mole 放在流程最后，避免它拖住别的步骤。
- zsh：`rm dir/*` 没匹配会报错并中止整条命令。
- `lsof +D` 会把你自己 shell 的当前目录算进去；检查前先 `cd` 到别处。
- 模拟器删除后，项目里记录的 UDID 会失效，要同步更新记录或记忆文件。
- 删除 Godot 安卓模板 `android/build` 之前，确认导出脚本会自动重装。
- 把审计报告和备份放在要删除的目录之外，也不要放进 git 仓库。
